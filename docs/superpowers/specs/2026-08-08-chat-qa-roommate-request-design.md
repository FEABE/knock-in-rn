# 채팅 QA 5건 — 룸메이트 요청/매칭 UI 설계

출처: 채팅 QA (26.08.07 전달). 디자인 기준: Figma `V8HQXS3RuZUpmSsIP5uDQs` 채팅 섹션 `3496:87918`.

## 배경

채팅방(`components/chat/chat-room/`)의 룸메이트 요청 흐름이 디자인과 어긋나는 5가지 QA 지적:

1. 성별이 남성일 때도 여성용 빨간 칩이 표시됨
2. 룸메이트 요청 메시지(카드) UI가 디자인보다 큼
3. 요청 카드가 항상 메시지 목록 맨 아래 고정 → 이후 전송된 메시지가 카드 위에 쌓임
4. "이미 매칭됨" 상태가 Alert 팝업으로만 전달됨 (디자인은 배너+카드 상태 행)
5. 이미지 메시지를 크게 볼 수 없음

## 요구사항

### 1. 성별 칩 (헤더)

- 채팅방 헤더 성별 칩은 성별에 따라 분기: 남성 = 파란 칩(♂), 여성 = 빨간 칩(♀).
- `components/roommate/detail-screen/roommate-detail-screen.view.tsx`의 `GenderMetaChip`(남 `#E7F4FE`/`#0B78CB`, 여 `#FDEFEC`/`#DE3412`)과 동일한 시각 언어. 공용 컴포넌트로 추출해 두 화면이 공유한다.

### 2. 룸메이트 요청 카드 축소

- `RoommateRequestCard`를 Figma 카드 스펙(프레임 `3325:40413` 내 카드)에 정확히 맞춘다 — 헤더 바/본문 패딩·타이포·radius·버튼 높이 모두.
- 상태 행 3종(수락됨/상대 매칭됨/매칭 후 수락 불가)도 디자인 스펙을 따른다 (`3496:81367`, `3496:82015`, `3496:80303`).

### 3. 요청 카드 타임라인 앵커링

- 카드는 요청이 발생한 시점의 위치에 타임라인 안에 렌더된다. 이후 도착/전송 메시지는 카드 아래로 이어진다.
- `RoommateRequestState`에 `createdAt`을 추가한다(서버 응답에 이미 존재, 매핑만 누락). `createdAt`이 없으면 기존처럼 맨 아래 폴백.
- 오래된 채팅방에서는 카드가 스크롤 중간(요청 시점)에 위치한다 — 의도된 동작(사용자 확인됨).

### 4. 매칭 상태의 UI화 (팝업 제거)

- "이미 매칭됨" 계열 상태는 Alert가 아니라 화면 상태로 표현한다:
  - 상단 배너(빨강 계열): 상대가 매칭됨 → "상대방이 다른 분과 룸메이트가 되었어요", 내가 매칭됨 → "이미 다른 분과 룸메이트가 되었어요" (`3496:82015`, `3496:80303`).
  - 요청 카드 하단 상태 행: "상대방이 매칭된 상태예요" / "매칭 후에는 수락할 수 없어요".
  - 수락 성사 시: 타임라인에 "룸메이트가 되었어요" 시스템 칩 표시 (`3496:81367`), 팝업 없음.
- 역할별 문구 판정(EXPIRED가 어느 쪽 매칭인지)은 백엔드 semantics 조사 결과를 따른다.
- 순수 네트워크 오류/기타 실패의 Alert는 유지한다. "이미 매칭됨" 류 서버 응답만 화면 상태 갱신으로 전환.

### 5. 사진 전체화면 뷰어

- 이미지 버블 탭 → 전체화면 뷰어 (`3589:28288`): 검정 배경, 좌상단 X 닫기, 헤더 중앙에 상대 이름, 이미지 중앙 배치.
- 신규 공용 컴포넌트 1개로 구현. 내 이미지/상대 이미지 모두 지원.

## 비범위 (YAGNI)

- 이미지 핀치줌·저장·공유 기능 (디자인에 없음)
- 채팅 목록/다른 화면의 칩 변경 (QA 범위는 채팅방)
- 요청 카드 외 메시지 버블 스타일 변경

## 검증

- 테스트 인프라 부재 → `npx tsc --noEmit` + `npx expo lint` + 웹/모의 데이터 렌더 확인.
- 기존 자동 스크롤(메시지 추가 시 scrollToEnd) 동작이 카드 앵커링 후에도 유지되는지 확인.
